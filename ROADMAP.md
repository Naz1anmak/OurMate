## 🔼 Обновление aiogram (блокер для всего остального)

Сейчас в проекте `aiogram==3.26.0`, это Telegram Bot API 9.5. Всё, что описано
ниже, требует более новых версий, поэтому апгрейд идёт отдельной задачей —
с зелёными тестами до и после, без попутных фич.

| Версия aiogram | Bot API | Что даёт |
| --- | --- | --- |
| 3.28.x | 10.0 | rich-сообщения, черновики; в 3.28.0 баг с медиа в опросах — брать 3.28.1+ |
| 3.29–3.31 | 10.1–10.3 | типы rich-блоков, кнопки внутри сообщений, эфемерные сообщения |

Апгрейд через 9.5 → 10.3 меняет поведение нескольких хендлеров, поэтому
разбить на два шага: сначала 3.28.2 (проверить поллинг, черновики, эмодзи),
потом 3.31.0.

## ⏹ Кнопка «Стоп» для стрима в ЛС

`sendMessageDraft` в Bot API 10.3 получил `can_stop` и `keep_on_stop`. Это
нативная кнопка остановки генерации: пользователь жмёт — Telegram сам
прекращает показ черновика, а `keep_on_stop` решает, оставить накопленный
текст или убрать.

Сейчас стрим в ЛС гасится вручную (пустой `text` в черновике). Нативная
кнопка убирает костыль и делает поведение таким же, как в официальных
клиентах.

Где: `src/bot/handlers/llm_flow.py` — там три места с `SendMessageDraft`.

## 🚫 `disabled` на инлайн-кнопках

В Bot API 10.3 у `InlineKeyboardButton` появился флаг `disabled` и отдельный
тип `DisabledButton`. Кнопку можно показать неактивной, а не убирать из
разметки.

Пригодится там, где сейчас клавиатура пересобирается целиком:
- пинг-лист и списки — кнопка «записаться», когда участник уже в списке;
- напоминания — кнопки подтверждения после того, как выбор сделан.

Выигрыш в том, что раскладка не «прыгает» и видно, что действие
существует, но недоступно.

## 📊 Расписание rich-блоками

Bot API 10.0 принёс rich-сообщения: таблицы (`RichBlockTable`), заголовки
разной величины, раскрывающиеся цитаты. В 10.3 к таблице добавился
`is_compact`.

Расписание сейчас — текст с выравниванием пробелами, который на узких
экранах разъезжается. Таблица решает это на уровне клиента.

Осторожно с двумя вещами:
- premium-эмодзи: `PremiumEmojiMiddleware` подменяет символы в
  `SendMessage`/`EditMessageText`. Для rich-блоков нужна отдельная ветка,
  иначе эмодзи в таблицах станут обычными;
- закреп расписания редактируется, а не пересылается — надо проверить, что
  rich-сообщение вообще редактируется через `editMessageText`.

## 🆔 Автодобор `user_id` по нику

`_refresh_usernames` умеет обновлять ник, только если `user_id` уже
известен: получить id по `@нику` через Bot API нельзя. Поэтому у новых
записей в `birthdays.json`, заведённых из списка группы, `user_id` остаётся
`null`, и упоминание уходит текстом без ссылки.

Идея: на любом сообщении в чате сверять `username` из апдейта с записями,
где `user_id is null`, и проставлять id. Заполнится само за пару дней
активности чата и закроет проблему для всех будущих пополнений.

Где: `src/bot/handlers/chat_member.py` или отдельный middleware.

## 🚪 Автоматический перевод в отчисленных

Бот не проверяет, состоит ли человек в беседе, перед поздравлением.
Единственный фильтр — `is_active` (подписан и доступен в ЛС), а
`status: "-"` только переключает шаблон промпта. Перевод в отчисленных
сейчас руками в JSON.

Можно ставить `status: "-"` автоматически из `on_chat_member_update` при
выходе или исключении. Удалять запись при этом не надо — история дней
рождения остаётся.

## 💬 Эфемерные сообщения

`EphemeralMessageParameters` в Bot API 10.3 — сообщение, которое Telegram
удаляет сам. Подходит для служебных ответов, которые сейчас копятся в
чате: сообщения о лимитах, «нет пар», ошибки валидации ввода.
